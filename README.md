# AI Assistant

A production-grade AI assistant built from scratch, following a 20-phase
roadmap. See the current phase below.

## Status

- **Phase 7 (Large Language Models)**: M1 complete — a pre-trained
  causal LM (`HuggingFaceTB/SmolLM2-135M`, runs on CPU, lazy-loaded on
  the first unanswered question) now answers whatever the rules cannot
  (`app/llm/generator.py`). Ask "what is 2+2" and get "4". Priority
  stays: rules → taught facts → long-term memory → LLM → echo. It
  degrades to the echo offline, and honestly reveals its limits (a 135M
  base model has no world model: it answered "how many continents" with
  "14", and parroting the question is detected and rejected). M2 adds a
  conversation context window. `LLM_ENABLED`/`LLM_MODEL_ID`/
  `LLM_MAX_NEW_TOKENS`/`LLM_TEMPERATURE`/`LLM_LOCAL_FILES_ONLY` in
  `app/config.py`.
- **Phase 6 (Transformers)**: complete — the transformer architecture
  built from scratch (`app/transformer/`): sinusoidal positional
  encoding, multi-head scaled dot-product attention, pre-norm encoder
  blocks, a word tokenizer/vocab, and a `TransformerIntentClassifier`
  with the same drop-in API. The controlled experiment is the honest
  punchline: **from-scratch attention trails the Phase 4 baseline
  (60.5% vs 71.1%)** — without pre-training, attention alone is worse
  at this data scale. Selectable via `INTENT_MODEL_KIND="transformer"`;
  it is the architectural foundation Phase 7 loads language knowledge
  into.
- **Phase 5 (Deep Learning)**: complete — a PyTorch neural intent
  classifier (`app/dl/`): the same TF-IDF features through a
  hidden-layer MLP trained with a real backprop loop, early stopping,
  and a controlled head-to-head against the Phase 4 baseline. Honest
  result: **71.1% vs 71.1% tie** — with 149 examples depth buys
  memorization (train acc → 100%) but not generalization, which is why
  the simpler logistic regression stays the router's default
  (`INTENT_MODEL_KIND="linear"`) and the neural model is one config
  flip away (`"neural"`). This is the on-ramp to Phase 6.
- **Phase 4 (Machine Learning)**: complete — a supervised intent
  classifier (`app/ml/`): TF-IDF + logistic regression trained on 149
  labeled examples, honest held-out evaluation (~71% accuracy; the
  honest tradeoff vs. the Phase 7 LLM), and a persisted artifact
  (`python -m app.ml.train` regenerates it). The Assistant now routes
  through `IntentRouter` — ML steers the reply branch only when
  confidence ≥ threshold (default 0.5, config-gated), the deterministic
  rules confirm details and remain the safety net. Latest phase-by-phase
  status lives in [ROADMAP.md](ROADMAP.md).
- **Engineering hardening**: rate limiting on `POST /chat` (fixed-window
  per-IP, 429 + Retry-After, probes exempt) and pagination on
  `GET /history` (`limit` 1–500, `offset` ≥ 0, self-describing
  `total`/`limit`/`offset`). 234 passing tests.
- **Phase 10 (Memory System) preview**: consolidation + retrieval of
  long-term memory: `MemoryExtractor` distills statements, dedup stores
  them, and the Assistant answers across sessions (rule-based until RAG
  in Phase 9 / full memory in Phase 10). CLI has `/remember` and
  `/memory`.
- **Phase 3 (Databases)**: complete. Schema versioned and reversible
  with Alembic; app runs `alembic upgrade head` on startup.
- **Phase 2 (Backend Development)**: complete — FastAPI app, routes /
  schemas / services layering, dependency injection, thread-safe
  chat service.
- **Phase 1 (Programming Fundamentals)**: complete — REPL assistant with
  persistent memory, exception hierarchy, atomic file writes, git/GitHub.

## Requirements

- Python 3.12+ (verified with 3.14)

## Setup

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
```

## Run the web server

```powershell
.\.venv\Scripts\python -m uvicorn app.main:app --reload --port 8000
```

- Health check: <http://127.0.0.1:8000/api/v1/health>
- Interactive API docs (auto-generated by FastAPI): <http://127.0.0.1:8000/docs>

## API examples

Chat with session `demo`:

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/v1/chat `
  -ContentType "application/json" `
  -Body '{"session_id":"demo","message":"hello"}'
```

Read a page of that session's history (pagination hardening):

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/v1/history/demo?limit=50&offset=0"
```

The response includes `total`, `limit`, and `offset` so clients can
page through long conversations. Sending more than 30 chat messages per
minute from one IP returns `429` with a `Retry-After` header.

## Database migrations (Alembic)

The schema is managed by Alembic — every change is a versioned,
reversible migration. The server applies pending migrations on startup,
so a fresh checkout just works; there is no manual step to run the app.

```powershell
# Generate a new migration from model changes (review it first!)
$env:DATABASE_URL = "sqlite:///..."  # only when not using the default
.\.venv\Scripts\python -m alembic revision --autogenerate -m "describe change"

# Apply / roll back
.\.venv\Scripts\python -m alembic upgrade head
.\.venv\Scripts\python -m alembic downgrade -1
```

`alembic/versions/` holds the migration files; the `alembic_version`
table in the database records which revision is currently applied.

## CLI usage

```
You> HELLO!!
Hello! I'm Aria. How can I help?
You> what is your name
My name is Aria.
You> /stats
I remember 4 messages (user=2, assistant=2) across my sessions.
You> /about
I am Aria, version 0.1.0. Currently: Phase 1 - Programming Fundamentals.
You> /help
Commands: /help  /stats  /about  /exit
You> /exit
```

Conversations are saved to `data/history.json` and reloaded on the next
start — the seed of long-term memory. The web server grew per-session
persistence in Phase 3 (Databases).
