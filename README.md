# AI Assistant

A production-grade AI assistant built from scratch, following a 20-phase
roadmap. See the current phase below.

## Status

- **Phase 6 (API Hardening)**: Milestone 2 complete — history is
  paginated (`GET /history/{id}?limit=&offset=` with a 500-row cap and
  self-describing `total`/`limit`/`offset`), so one request can never
  load a session's unbounded history. Milestone 1 added rate limiting:
  a fixed-window per-IP cap on `POST /chat` returning 429 + Retry-After
  (health/ready probes exempt). 140 passing tests.
- **Phase 5 (Memory System)**: complete — consolidation + retrieval of
  long-term memory: `MemoryExtractor` distills statements, dedup stores
  them, and the Assistant answers across sessions (rule-based until LLM
  in Phase 7 / RAG in Phase 8). CLI has `/remember` and `/memory`.
- **Phase 4 (Database Integration)**: complete. Schema versioned and
  reversible with Alembic; app runs `alembic upgrade head` on startup.
- Phase 1 (Programming Fundamentals) complete — REPL assistant with
  persistent memory, exception hierarchy, atomic file writes, git/GitHub.

## Requirements

- Python 3.12+ (verified with 3.14)

## Setup

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
```

## Run the web server

```powershell
.\.venv\Scripts\python -m uvicorn app.main:app --reload --port 8000
```

- Health check: <http://127.0.0.1:8000/api/v1/health>
- Interactive API docs (auto-generated by FastAPI): <http://127.0.0.1:8000/docs>

## API examples

Chat with session `demo`:

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/v1/chat `
  -ContentType "application/json" `
  -Body '{"session_id":"demo","message":"hello"}'
```

Read a page of that session's history (Phase 6: paginated):

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/v1/history/demo?limit=50&offset=0"
```

The response includes `total`, `limit`, and `offset` so clients can
page through long conversations. Sending more than 30 chat messages per
minute from one IP returns `429` with a `Retry-After` header.

## Database migrations (Alembic)

The schema is managed by Alembic — every change is a versioned,
reversible migration. The server applies pending migrations on startup,
so a fresh checkout just works; there is no manual step to run the app.

```powershell
# Generate a new migration from model changes (review it first!)
$env:DATABASE_URL = "sqlite:///..."  # only when not using the default
.\.venv\Scripts\python -m alembic revision --autogenerate -m "describe change"

# Apply / roll back
.\.venv\Scripts\python -m alembic upgrade head
.\.venv\Scripts\python -m alembic downgrade -1
```

`alembic/versions/` holds the migration files; the `alembic_version`
table in the database records which revision is currently applied.

## CLI usage

```
You> HELLO!!
Hello! I'm Aria. How can I help?
You> what is your name
My name is Aria.
You> /stats
I remember 4 messages (user=2, assistant=2) across my sessions.
You> /about
I am Aria, version 0.1.0. Currently: Phase 1 - Programming Fundamentals.
You> /help
Commands: /help  /stats  /about  /exit
You> /exit
```

Conversations are saved to `data/history.json` and reloaded on the next
start — the seed of long-term memory. The web server will grow
per-session persistence in Phase 2, Milestone 3.
